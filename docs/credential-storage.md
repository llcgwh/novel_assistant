# WebDAV 密码存储与升级

WebDAV 密码通过 JPA 转换器以 AES-256-GCM 加密后写入数据库，每次写入使用新的随机 nonce。数据库列不再存放明文；应用调用 WebDAV 时在内存中解密。小说接口、JSON 导出、含图片备份和实体日志均不包含密码。此功能不改变 WebDAV 连接参数和前端配置方式。

## 密钥位置

默认在后端工作目录的 `.secrets/webdav.key` 中生成一个随机 32 字节密钥，文件内容是 Base64。首次需要加密时才生成。macOS/Linux 上新建目录权限为 0700、文件权限为 0600；Windows 使用文件系统默认 ACL，请将目录访问权限限制为运行服务的账户。

可用环境变量配置：

- `NOVEL_CREDENTIAL_KEY_FILE`：密钥文件路径，生产部署建议使用固定的绝对路径，并持久化此文件。
- `NOVEL_CREDENTIAL_KEY`：直接提供 32 个随机字节的 Base64 编码；设置后优先于文件。不合法的值会报错，不会退回自动生成密钥。

**单独安全备份密钥。** 数据库备份若用于恢复现有 WebDAV 凭据，必须同时保留对应密钥。含图片的小说备份不携带密码或密钥，跨设备恢复小说后仍使用目标设备自己的 WebDAV 配置。

`.secrets/` 已加入 Git 忽略规则。不要将密钥加入 Git、日志或可公开分享的备份。不要直接更换密钥：密钥轮换及旧密钥重加密工具尚未实现。

## 已有安装升级

1. 保留数据库备份；已有密钥文件也应单独备份。
2. 将 `novels.webdav_password` 列扩为 TEXT，以容纳 nonce、认证标签和 Base64 开销。当前默认配置 `spring.jpa.hibernate.ddl-auto=update` 会根据实体定义更新；禁用自动更新的部署须先执行 `database/migration_v4.sql`。
3. 用固定工作目录或固定密钥路径启动新版后端。启动迁移先验证现有密文是否可解密，再在数据库事务中迁移旧明文。空密码保持不变，已加密的行不会再次迁移。

升级代码不会改写旧 SQL dump、旧日志或其他历史副本。正在运行旧版本的实例应先停止，避免继续向同一数据库写入明文。

## 故障处理

- 密钥丢失：恢复原密钥后重启。解密时不会生成替代密钥，也不会把失败结果当成空密码覆盖数据库。
- 密钥错误或密文损坏：启动迁移报错并保留原数据，检查密钥与数据库备份是否配套。
- `enc:` 是数据库密文保留前缀。极少数旧明文密码若原本以此前缀开头，升级会拒绝猜测其格式；需要在升级前重设 WebDAV 应用密码。
- 普通小说编辑也会把尚未迁移的旧明文重新保存为密文。

本批通过 H2 测试验证列内容、长 Unicode 密码、迁移与故障行为，未直接启动用户的 PostgreSQL 数据库或执行真实数据迁移。
